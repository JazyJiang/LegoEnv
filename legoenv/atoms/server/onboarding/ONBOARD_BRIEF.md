# ONBOARD BRIEF — attach one environment spec to the pack builder (workstream B)

You onboard ONE app: `{APP}`. Its raw spec (tools + entities, generated by the Env Compiler) is at
`apps/base_specs/{APP}.spec.json`; the screening note about it is
`pack_dpsk/cards/specs/{APP}.screen.json`. When you are done, `python3 pack_dpsk/contract/onboard_check.py {APP}` must print `ONBOARD {APP} PASS`.

## Read first
`pack/newspecs/register.py` (the pattern: SERVER/PFX/CONTENT/NOTES/LOGIN + seeding helpers + the obs hook, for 7 apps), `pack/newspecs/README.md`,
`pack/packlib.py` docstring + `World`/`Contract`/`simulate`, `pack_dpsk/contract/capability_card_schema.json`, `pack_dpsk/contract/vocab.json`
(kind_tools / check_kinds / carriers), and `smoke/PATCHES.md` (patches the 19 existing bases needed: id types, guards, session scoping).

## Deliver (all under `pack/newspecs3/{APP}/` plus one file in base_specs)
1. `pack/base_specs/{APP}.spec.json` — the raw spec with the patches it needs: a persona account (id 1) in the account entity with a known
   password, `sign_in`-style login working, id-typed args that must accept integers, guards that block a signed-in persona, whole-list reads
   that cannot stay under 12k (add a filter arg or a search tool). Record every patch in `PATCHES.md` next to the register file.
2. `register.py` — registers the app into packlib exactly like `newspecs/register.py` does (SERVER, PFX=`{APP}`, CONTENT = the entities that
   hold task content, NOTES = the one-paragraph system note telling an agent how to sign in and which read/write tools matter, LOGIN = (tool,
   username field)); adds an `obs_report` hook for its whole-list reads; exposes seeding helpers; and exposes
   `smoke_seed(W) -> (steps, preds)`: seeds >= 3 realistic content rows + one policy text in a carrier field, returns gold steps
   `[(app, tool, args), ...]` that perform one write, and >= 3 contract predicates `[(id, semantic, pred, negative), ...]` incl. one negative,
   built with packlib's `SEL/F/AND/CNT` on this app's entities.
3. `capability_card.json` — per the schema: kinds → the write tools that realize them (only kinds from the vocabulary, or `other:<name>` to propose
   a new one), check_kinds the entities can support, carriers as `{carrier: {entity, field}}`, login, content_entities, seed helper names,
   `tool_families_to_keep` (prefixes; a world with this app must stay <= 350 tools), obs_reads, known_patches.
4. Run the check, fix until PASS. Then a 6-line final message: what the app is, which kinds/carriers it supports, what you patched, what you could
   not make work.

## Rules
- Never edit `pack/packlib.py`, `pack/accept.py`, `pack/newspecs/*`, other apps' bases, or anything in the supplied read-only source tree.
- Do not invent tools: if the spec lacks a write the app obviously needs, note it in the final message; do not add tools to the spec.
- Persona account id must be 1; seeded ids integers; column names valid tool-argument names (`^[a-zA-Z0-9_.-]{1,64}$`).
